# Conventions

Stable rules for every device in this repo. Device-specific state lives in `devices/<name>/HANDOFF.md`.

## Target and delivery

- Live 11 on an Intel Mac: Max 8 (Live's bundled version), the old ES5 `js` engine (no `let`, arrow functions, classes, template strings).
- A device ships as one folder (`<Name>/`): the `.amxd`, its JS views and its external. GitHub Actions builds the C++ external for Mac (universal: Intel + Apple Silicon), packages the folder and publishes it as a release zip. The user downloads it, unzips the folder into `~/Documents/Max 8/Library/`, runs `xattr -dr com.apple.quarantine` on it once, and drops the `.amxd` into Live.
- Engines are C++ (header-only, no Max dependencies) so the exact code is tested offline on Linux (`tools/tests`); the Max wrapper is thin. No third-party Max packages.
- The `.maxpat` / `.amxd` are generated by `tools/build_device.py`: never hand-edit them.
- After replacing an external, the user quits Live completely (Live keeps a loaded external in memory).
- Every build bumps a version string printed to the Max console at load (`<device>: <part> <YYYY-MM-DD><letter>`), so the user can see which files Live loaded.
- After replacing files, the user loads a fresh copy of the device: a copy saved inside a set keeps the old layout.

## Working with the user

- Discuss and propose first; build only after an explicit "go".
- The UI comes first: show a mockup of how the device will look and get it approved before any final build.
- Explain in plain words with small examples.
- Keep Live test requests minimal: simulate first; ask for a Live test only when nothing else can tell (e.g. gen~ compiling silently to zero).
- Commit every build to GitHub; push when the user agrees.

## Naming and isolation

- Every buffer, dict, send/receive, Global and named object that is shared inside a device starts with `---` (Live replaces it with a per-device id). Nothing device-wide may use a fixed name: duplicate devices must never crosstalk.
- UI → `prepend <name>` → one receiver per role (e.g. `---brain`).

## Threads (C++ engines)

- The audio thread never allocates, locks or frees. The main thread talks to it through a command ring; it answers through a report ring; big data (tables, loops) is handed over by pointer and freed back on the main thread.
- Every fade is S-shaped (smoothstep), at least 3 ms: no corner in the level, no click. The offline click test must pass.

## gen~ rules (learned the hard way, for gen~ devices)

- gen~ can compile a whole engine to zero output with no console error. Keep new code in patterns already proven in a playing engine; if sound disappears, bisect against the last playing version.
- Functions first. Loops only at top level; a loop that should not run gets length 0, not an enclosing `if`.
- Inside loops, all peeks first, then logic.
- No nested ternaries. Declare every local once, at top level, before use.
- In Live, writes (`poke`, History) inside `if` blocks can be dropped. Make writes unconditional; choose the value or the target index with ternaries.
- Don't call user functions with side effects (e.g. an RNG) inside `if` blocks.
- Brain → engine requests: the brain counts a request number up; the engine acts once when the number changes. The engine never writes a slot the brain writes.

## Saving in the Live set

Proven in Live 11.3 (Lifegiver 15e, lifegiver-audio repo): a hidden `[pattr]` blob parameter holding a number list is saved in the set and restored on reopen, per device, no crosstalk. For a generated device:
- **Parameter mode of a plain object (`pattr`, `dict`) goes in `saved_object_attributes`**, as Max writes it: `"saved_object_attributes": {"parameter_enable": 1, "parameter_mappable": 0}` (plus the box-level `"parameter_enable": 1`). A box-level `parameter_enable` alone only works for UI objects (`live.dial` etc.); on a pattr it is silently ignored: the pattr holds its value during the session, but Live saves an **empty blob**, so everything is lost on reopen.
- The pattr gets `"varname": "<its name>"`; `valueof`: `parameter_type` 3 (blob), `parameter_invisible` 1 (Stored Only), Initial Enable 0 and no `parameter_initial`.
- Store numbers, never a dict name: a pattr given `dictionary <name>` saves only the name. Text goes in as byte values (UTF-8, so non-English letters survive); no new symbol per save (Max never frees symbols).
- One Max message holds at most 32767 items: keep each store under 30000 numbers. A bigger state is split over several stores (one pattr each), and each store is rewritten only when its part changed.
- Numbers may come back as 32-bit floats: round before saving, and split whole numbers above 2^24 (sample positions) in two.
- Live restores the value as the device loads. Still ask more than once on load (0 / 300 / 800 ms), call it a new device only after 1.5 s, and save nothing before that. A pattr echoes every value it is given: recognise your own save coming back.
- Debug: a `.als` is gzip'd XML. `gunzip -c set.als` and look at the device's `<BlobSlot>`: empty `<Blob />` means nothing was stored.

## Max JS rules

- Dicts turn 1-element arrays into scalars; no nested arrays, no `null` (use a converter like `toArr`).
- Use `Object.prototype.toString` checks, not `instanceof Array`.
- `save` is a reserved function name.
- Long work runs in chunks via `Task`, so Live never freezes.

## Patching

- A comma in a message box splits the message.
- `[t a a]` can send the symbol "a"; fan out with plain patch cords instead.
