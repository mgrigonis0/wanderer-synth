# Wanderer — Handoff

_Last updated: 2026-10-16_

## What it does
A Max for Live instrument (Live 11 / Max 8, Intel Mac). Up to 16 audio files are sliced (Hits or Notes detection); each
file's stochastic clock plays its slices in time with Live (Free) or repeats a captured/generated loop (Lock). Per-file
settings have a value, a per-hit range (outer ring, scaled by Chaos) and a mode (fixed / rnd / walk). Random, Macro,
Mutate, 8 memory slots with Slide, global Quant, Allow switches, and an output chain (Even, Comp, Stereo, Volume, Limit).

## Structure
- `source/engine/` (header-only C++17, no Max deps): `params.h` (param table `PDEF`, scales), `types.h` (slice table,
  loops, command/report rings, `chooseSlice`), `player.h` (audio thread: clock, Lock, bursts, 6 voices × tape/grain, SVF,
  comp, limiter), `analysis.h` (Hits/Notes detection, attacks), `model.h` (main thread: files, Random, capture, patterns,
  memory, Mutate, load/save logic), `state.h` (`StateDoc` ↔ number list codec, `putBig`/`getBig`), `version.h`.
- `source/projects/wanderer_tilde/wanderer_tilde.cpp`: Max wrapper (buffers `---w1..16`, slicing worker thread,
  `persistFile`, info outlet 2, store outlet 3). Built by CMake + `.github/workflows/wanderer.yml` (tests, universal mac
  build, release zip `wanderer-latest`).
- `Wanderer/`: shipped folder. Views: `wanderer.page.js`, `.wave.js`, `.files.js`, `.memory.js`, `.gr.js`; `wanderer.drop.js`
  resolves dropped names. `Wanderer.amxd/.maxpat` are generated by `tools/build_device.py` (never hand-edit; reads `version.h`).
- `tools/tests/` (`harness.h` fake host with fake stores + synthetic audio, `engine_test.cpp`): build with
  `g++ -std=c++17 -O2 -o engine_test engine_test.cpp -lpthread`; `./engine_test stores` runs the saving tests.
- `design/ui-mockup.dc.html`: the approved UI (canvas "Wanderer UI").
- Flow: `phasor~ 1n @lock 1` → `wanderer~ ---wnd` → `plugout~`. Controls → `prepend <name>` → wanderer~. Outlet 2 → every
  view and `[route fstate cleararm gset relink]`.
- Saving: outlet 3 → `[route getstate st0 … st8]`. `getstate` bangs all 9 `[pattr st<k>]`; `st<k> <numbers>` sets one.
  Each pattr → `[prepend statelist <k>]` → wanderer~ → `Model::stateFrom`. Store 0 = `writeState` (files, slicing,
  settings, loops), stores 1–8 = `writeSlot` (one memory slot each).

## Parameters
Per file: tabs clock, slice, play, pitch, env, filter, repeat, grain, detect (`PDEF` in `params.h`; layout `PAGES` in
`wanderer.page.js`). Global Live parameters: Quant, Density, Length, Quant To, Lock Mode, Lock Bars, Macro, Chaos, Mutate,
Pitch, Scale, Allow Trip/Dot/Pitch/Rev/Buzz/Rep, Random all, Random Depth, Clear all, Slide, Store, Clear Slot,
Detect Sens / Min Len / Method, Even, Comp, Stereo, Volume, Limit, Drop (file, invisible 2), State and Mem 1–8 (hidden
blobs, Stored Only, no initial value).

## Decisions (and why)
- C++ engine, not gen~: gen~ compiled silently to zero and Live dropped writes inside `if`; C++ is tested offline as is.
- One object for all 16 files; every name derives from the `---` prefix (`wanderer~ ---wnd` → prefix = arg minus "wnd").
- Model on the main thread, player on the audio thread; rings between them; tables/loops handed over by pointer.
  perform works in blocks of ≤ 4096 samples on buffers made in `new` (nothing allocated on the audio thread).
- Saving = 9 stores, not 1: a full session (16 locked files, 8 slots) is ~67 000 numbers, one Max message holds 32 767.
  Biggest store in the heavy test: ~12 400. A slot's store is rewritten only when that slot changes; identical lists are
  never re-sent (no undo steps). A store still over 30 000 is saved without its loops, with a line in the Max window.
- Loops saved compactly: only knobs whose offsets vary, two offsets per number (0..4094, exact in float32). Every value
  is rounded to float32 before saving and hashed (Live may keep 32-bit numbers); slice starts are split in two (> 2^24).
- Load (`Model::init/tick/stateFrom`): asks at 0/300/800 ms; "new device" at 1.5 s; a valid state up to 10 s late still
  wins. Our own echo is skipped; a later different list (e.g. Live's undo) is not taken: the device re-saves what plays.
- Drops are ignored until the state is settled (the Drop strip re-sends its last file when a set opens).
- Mutate re-draws a loop's hits after each pass; the player swaps it in place (same hits, keeps its position).
- Dropped names: Live hands `live.drop` only a name (`TEMP-655_3870941970_<file>`). `wanderer.drop.js` (`new File`) finds it;
  buffer~ loads it by name; once loaded it is copied to `~/Music/Wanderer Samples/<name>.wav` (float WAV), that path is saved.
- Buttons send `bang`: the model reads any word as the default value ("grand bang" = "grand 1").
- Allow block 2 × 3 (Trip Dot / Pitch Rev / Buzz Rep), all off by default and after Clear all.
  - Buzz off: bursts never faster than their spacing nor closer than 30 ms; loops ≥ 50 ms; grains ±25 % length wobble.
  - Rep off: no bursts and no Loop (settings kept).
- Random: Loop on in about 1 roll of 5 and then with its range; off = range 0 (was 42 % of hits looping).
- All fades S-shaped (≥ 3 ms attack, 4 ms release, 5 ms cut); resonance fades out above ~10 kHz.
- Hits detection uses plain + brightened energy (hats on kick tails); Notes = log spectral flux + local median.
- UI: section panels only (`background 1`, first in the box list); global cells 44 px so Live's labels fit (device 1144 px).

## Rejected approaches
- A dict (or its name) in the pattr, a box-level-only `parameter_enable` on a pattr: Live saves an empty blob / a name.
- One store for everything: over Max's message limit in a full session.
- FluCoMa: extra install; its analysis queue got stuck in long sessions.
- 16 hidden `live.drop` file holders fed with `set`: Live never handed anything back at load.
- A full-size background panel: drawn over every control in Live.
- Resolving dropped names in the external (`locatefile_extended`): can't find Live's TEMP copies.

## Known issues
- Old sets (15k/15l, legacy device) hold nothing usable: they open as a new device.
- Live's undo of a save step is not followed (the device keeps what plays and saves it again).
