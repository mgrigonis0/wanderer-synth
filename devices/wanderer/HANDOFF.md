# Wanderer — Handoff

_Last updated: 2026-10-15_

## What it does
A Max for Live instrument (Live 11, Max 8, Mac). Up to 16 audio files are sliced (Hits or Notes detection) and each file's
stochastic clock plays its slices in time with Live (Free), or repeats a captured or generated loop (Lock). Per-file
settings have a value, a per-hit range (scaled by Chaos) and a mode (fixed / rnd / walk). Random, Macro, Mutate, 8 memory
slots with Slide, global Quant, and an output chain (Even, Comp, Stereo, Volume, Limit).

## Structure
- `source/engine/`: header-only C++17, no Max deps. `params.h` (param table, scales), `types.h` (tables, loops, command/report
  rings), `player.h` (audio thread: clock, Lock, repeats, 6 voices × tape/grain, SVF, comp, limiter), `analysis.h`
  (Hits / Notes detection, attacks), `model.h` (main thread: files, Random, capture, patterns, memory, Mutate, state doc).
- `source/projects/wanderer_tilde/wanderer_tilde.cpp`: Max wrapper (buffers, worker thread for slicing, dict save, outlets).
- `Wanderer/`: the shipped folder. `*.js` views (page, wave, files, memory, gr). `Wanderer.amxd/.maxpat` are generated by
  `tools/build_device.py` (never hand-edit).
- `tools/tests/`: `harness.h` (engine + fake host + synthetic audio), `engine_test.cpp`. CI: `.github/workflows/wanderer.yml`.
- Flow: phasor~ 1n (bar phase) → wanderer~ → plugout~. Controls → `prepend name` → wanderer~. wanderer~ outlet 2 → every view
  (each ignores what isn't its own) and `[route fstate cleararm gset getstate dictionary relink]`.

## Parameters
Per file (page tabs): clock, slice, play, pitch, env, filter, repeat, grain, detect — table `PDEF` in `params.h` (+ page layout
`PAGES` in `wanderer.page.js`). Global Live parameters: Quant, Density, Length, Quant to, Mode (Free/Lock), Bars, Macro,
Chaos, Mutate, Pitch, Scale, Allow ×4, Random all, Depth, Clear all, Slide, Store, Clear slot, Detect Sens / Min len / Method,
Even, Comp, Stereo, Volume, Limit, plus the hidden blob `State` (pattr).

## Decisions (and why)
- C++ engine instead of gen~: gen~ compiled silently to zero and Live dropped writes inside `if`; C++ is tested offline as is.
- One object for all 16 files; every name derives from the `---` prefix (`wanderer~ ---wnd` → strip "wnd"), so duplicates never share.
- Model on the main thread, player on the audio thread; commands/reports through rings; tables/loops handed over by pointer and
  freed on the main thread. The player never allocates or locks.
- Mutate re-draws a loop's hits right after each pass and the player swaps it in place (same hits, keeps its position).
- Saved state = flat dict (keys like `f3.b`, `s2.f3.pat`) in a pattr blob; read once per load (pulled at `init`, 1.5 s fallback
  to "new device"); nothing is saved before that; identical saves are skipped. Slicing is saved too: a reload re-uses it.
- Dropped names are resolved in JS (`new File(name)` → foldername/filename): the external's locatefile_extended can't see Live's TEMP copies. Open question: does Live's TEMP-… copy survive reopening the set?
- Panels: only the section panels, `background 1`, first in the box list (proven by the legacy device). Never a full-size panel (it covered everything).
- live.drop is a parameter of type 4 (file), invisible 2: it only takes drops that way, and is never stored.
- Buttons send `bang`: the model reads any word as the default value ("grand bang" = "grand 1").
- Max 8 jsui flattens array arguments: no `set_dash([..], 0)`.
- Live restoring Mode / Method at load is ignored when equal to the saved value (no surprise re-capture or re-slice).
- Hits detection uses a plain and a brightened energy (hats on kick tails); Notes = log spectral flux + local median.
- All fades S-shaped, ≥ 3 ms attack / 4 ms release, 5 ms cut fade; resonance fades out above ~10 kHz (no ringing near Nyquist).
- Detection runs on a worker thread from a mono copy; the overview peaks come from the engine (no buffer reads in JS).
- Clear all needs two presses within 2 s (button shows "Sure?").

## Rejected approaches
- FluCoMa: an extra install, and its analysis queue got stuck in long sessions.
- gen~ engine (see above). Storing state as one long JSON symbol: every save would leak a big symbol.

## Known issues
- Global cells are 44 px so Live's labels fit (1/16, Notes, Pitch): the device is 1136 px wide (mockup ~930).
- Old Live sets with the legacy device don't load into this one (new device; no migration).
